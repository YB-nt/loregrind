# eval/groundtruth/ — 정답셋

**이 디렉터리는 에이전트가 읽어서는 안 된다.**

원본 심볼명이 에이전트 컨텍스트로 흘러들면 명명 정확도가 통째로 무의미해진다(§6).
`eval/leakage.py` 가 다음을 검사한다:

- 정답셋이 `artifacts/` 나 `.ghidra-projects/`(에이전트 접근 경로) 안에 있는가 → **차단**
- 정답셋이 `loregrind.db` 와 같은 디렉터리에 있는가 → 경고
- 에이전트 DB 에 정답 테이블이 있는가 → **차단**
- 원본 심볼명이 `functions.original_name` / `signature` / `decompiled` 에 남아 있는가 → **차단**

## 파일

| 파일 | 상태 |
|---|---|
| `groundtruth.example.json` | **스키마 참조용 예시.** 실제 측정에 쓰지 않는다 |
| `groundtruth.json` | 실제 정답셋. **아직 없다** — 생성 파이프라인이 미구현이다 |

스키마 전체 정의는 `docs/EVAL-SPEC.md` §2, 로더는 `eval/truthset.py`.
**모듈은 `truthset.py`, 데이터는 이 디렉터리다** — 이름을 겹치면 파이썬이 디렉터리를 네임스페이스 패키지로 잡아 모듈을 가릴 수 있다.

## 생성 절차 (미구현)

```
오픈소스 선정 → 컴파일러 x 최적화 격자로 빌드 → 심볼 스트립
  → 원본 심볼과 스트립 후 주소를 대조 → groundtruth.json
  → 같은 소스 함수의 다른 빌드끼리 pairs 산출
```

`pairs`(같은 함수의 다른 빌드)를 **생성 시점에 함께 산출한다.** 나중에 만들려면
전체 빌드를 반복해야 한다.

정답셋이 없으면 `make verify-holdout` 은 exit 3(미측정)으로 실패한다. 그것이
현재의 올바른 상태다 — 데이터가 없을 때 조용히 통과하는 게이트는 게이트가 아니다.
