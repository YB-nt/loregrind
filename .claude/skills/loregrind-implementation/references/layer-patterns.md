## 1. L1 추출 — Ghidra headless / PyGhidra

**두 세계를 분리한다.** Ghidra 스크립트(`scripts/`)는 Ghidra의 인터프리터에서 돌고 프로젝트 의존성을 쓸 수 없다. 오케스트레이션(`src/loregrind/extract/`)은 일반 Python이다.

```
src/loregrind/extract/runner.py   analyzeHeadless를 subprocess로 호출, 결과 파일 수집 → DB 적재
scripts/export_facts.py           Ghidra 안에서 돌며 사실을 JSONL로 덤프
```

**경계는 JSONL 파일로 삼는다.** Ghidra 스크립트가 DB에 직접 쓰지 않게 한다 — DB 드라이버를 Ghidra 인터프리터에서 쓰는 것은 취약하고, 실패 시 부분 커밋된 상태가 남는다. 스크립트는 덤프만 하고, 적재는 일반 Python이 트랜잭션으로 처리한다.

추출 대상: 함수 목록, 콜그래프, xref, 디컴파일 C, 문자열, 임포트, 데이터 타입.

**재개 가능성**: 함수 단위로 커밋한다(§4 원칙 4). 대형 바이너리에서 중간에 죽는 것은 정상 시나리오이므로, 이미 적재된 함수를 건너뛰고 이어갈 수 있어야 한다.

**추출은 런타임과 분리된다**(불변식 1). `extract/`의 코드가 `analyze/`에서 임포트되면 그 자체로 위반 신호다.

**Ghidra 단방향 apply**(불변식 2): 리네임·주석을 Ghidra 프로젝트에 반영하는 코드는 DB → Ghidra 방향만 존재한다. Ghidra의 현재 상태를 읽어 DB를 고치는 역방향 경로를 만들지 않는다.

## 2. L2 도구 — MCP 서버

MCP Python SDK로 서버를 만들고, `docs/PROJECT.md` §3의 도구만 노출한다.

**도구 설계 규칙:**
- 하나의 도구는 하나의 질문에 답한다. `get_function(addr)`은 함수를 주고, 호출자는 `get_callers(addr)`로 따로 묻는다. 한 도구가 그래프 전체를 반환하면 컨텍스트 예산이 통제 불가능해진다.
- 반환에 크기 상한을 건다. 디컴파일 C가 수천 줄인 함수가 존재하므로, 상한과 절단 표시를 도구 자체에 넣는다.
- 쓰기 도구(`rename_function`, `set_comment`, `record_*`)는 `run_id`를 서버 세션에서 주입한다. 에이전트가 인자로 넘기게 하면 빠뜨리거나 위조한다.
- `record_analysis`는 append-only 경로(`repo.supersede_analysis`)만 호출한다. 도구 계층에서 직접 SQL을 쓰지 않는다.

**금지**: `query(sql)`, `run_ghidra(...)`, 여러 동작을 플래그로 분기하는 만능 도구.

**도구 시그니처와 호출부는 감사의 교차 검증 대상이다.** 시그니처를 바꾸면 에이전트 프롬프트/루프의 호출부를 같은 커밋에서 함께 고친다.

## 3. L3 랭킹 — 결정론적 우선순위

```python
def rank_candidates(facts: FunctionFacts, weights: RankWeights) -> list[Candidate]:
    """같은 입력 → 같은 순서. LLM 호출 없음."""
```

신호: 의심 API 클러스터, 고신호 문자열 참조, capa 결과 매핑, 콜그래프 위치(도달 깊이·fan-in/out), 복잡도 이상치.

- 신호별 점수를 개별 필드로 남긴다. 합계만 저장하면 어떤 신호가 효과를 냈는지 어블레이션할 수 없다.
- 동점 처리에 `(-score, addr)` 같은 안정적 타이브레이커를 넣는다.
- 가중치는 `runs.config`에 기록되어야 어블레이션에서 조건을 구분할 수 있다.

**라이브러리 함수 필터를 랭킹 앞단에 둔다.** FID/시그니처 기반. 분석 대상을 절반 이하로 줄이는 단일 최대 효과의 최적화이므로, 성능 개선이 필요할 때 여기를 먼저 본다. 필터 결과는 폐기하지 말고 `is_library` 플래그로 저장한다 — 필터가 틀렸을 때 되짚어야 하고, 어블레이션 대상이기도 하다.

## 4. L4 분석 루프 — 요약 카드·서브에이전트·모델 계층화

**바텀업**: 콜그래프 말단부터 명명하고 올라간다. 위상 정렬 + 사이클(재귀) 처리가 필요하다 — 사이클은 SCC로 묶어 한 단위로 다룬다.

**요약 카드**: 상위 함수의 컨텍스트에는 하위 함수의 원시 디컴파일 코드가 아니라 압축 카드가 들어간다. 카드에 넣을 것: 제안된 이름, 한두 줄 요약, 사용 API, 신뢰도, `source`. 원시 코드를 넣기 시작하면 컨텍스트가 즉시 터지고, 이 프로젝트의 핵심 가설(계층 요약이 평면 컨텍스트보다 낫다)이 검증 불가능해진다.

**서브에이전트**: 콜그래프 서브트리를 위임하고 **카드 하나만 회수**한다. 서브에이전트의 중간 산출물이 상위 컨텍스트로 새어 들어오면 위임의 의미가 없다.

**모델 계층화**: 재검증은 저가 모델, 신규 상위 함수는 강한 모델. 어떤 모델이 어떤 판단을 냈는지는 `runs.model`로 추적되므로, 모델 선택 로직이 run 경계를 넘나들지 않게 설계한다.

**사전정보는 가설로 제시한다**(불변식 7). 검색으로 가져온 이전 분석 결과를 프롬프트에 넣을 때 "이 함수는 X다"가 아니라 "유사 함수가 X로 분석된 적이 있다 — 검증하라"로 제시한다. 결론으로 주면 §6의 반대율이 0으로 붕괴하고, 에이전트는 분석이 아니라 복사를 하게 된다.

## 5. L4 에뮬레이션 — 격리 검증

Unicorn 또는 Qiling. **함수 단위 격리만 한다.** 프로세스 생성, 실제 syscall 통과, 네트워크·파일시스템 접근을 허용하지 않는다.

```python
def emulate_function(addr: int, args: list[int], *, timeout_ms: int) -> EmulationResult:
    """메모리를 직접 구성하고 진입점을 addr로 잡아 실행. 외부 호출은 스텁으로 가로챈다."""
```

- 미매핑 메모리 접근·미지원 명령·타임아웃은 정상 결과다. 예외가 아니라 `EmulationResult.status`로 표현한다 — 스트립된 바이너리에서 대부분의 시도는 이렇게 끝난다.
- 명령 실행 수와 실행 시간에 상한을 건다. 무한 루프는 흔하다.
- 외부 API 호출은 스텁으로 가로채고, 어떤 API가 어떤 인자로 불렸는지 기록한다. 이 호출 로그가 가설 검증의 실제 증거다.
- 결과는 `hypotheses.result_json`에, `source='emulation'`으로 저장한다. 이 `source`가 쓰기 게이팅(불변식 6)을 통과시키는 근거이므로 정확히 기록한다.

가설 검증 흐름: 가설 기록(`status='open'`) → 실험 설계(`experiment_json`) → 에뮬레이션 → `confirmed` 또는 `refuted`로 새 행 기록. 반증된 가설은 `lessons` 컬렉션에 네거티브 예시로 들어간다.

## 6. 정규화와 해시

**정규화 없는 해시는 히트율이 사실상 0이다.** 해시 계산 함수는 정규화된 입력만 받도록 타입으로 강제한다:

```python
class NormalizedBody(str): ...          # 정규화를 거친 것만 이 타입이 된다

def normalize(decompiled: str) -> NormalizedBody:
    """주소·레지스터 할당·스택 오프셋을 제거한다."""

def code_hash(body: NormalizedBody) -> str: ...
```

원시 문자열을 받는 오버로드를 만들지 않는다 — 만드는 순간 누군가 그것을 쓴다.

제거 대상: 절대 주소, 레지스터 할당, 스택 오프셋. 보존 대상: 제어 흐름 구조, 상수, 호출 대상의 의미.

`cfg_hash`는 CFG 구조에서 별도로 계산한다. `code_hash`와 목적이 다르다 — `code_hash`는 "완전히 같은 함수인가"(증분 스킵용), `cfg_hash`는 "구조가 닮았는가"(검색 채널용).

**증분 재분석**: `code_hash`가 같으면 스킵하되, 바뀐 함수를 발견하면 **콜그래프 역방향으로 무효화를 전파**한다(깊이는 파라미터). 전파를 빠뜨리면 호출자가 낡은 요약 카드를 안고 간다.

## 7. 검색 채널과 RRF

각 채널은 독립적으로 순위 목록을 낸다. 채널을 켜고 끌 수 있게 만든다 — §6의 채널별 어블레이션이 이것을 요구한다.

| 채널 | 구현 요점 |
|---|---|
| 정규화 해시 | `code_hash` 완전 일치. 인덱스 조회 한 번 |
| API 집합 | 임포트 다중집합 Jaccard |
| 구조 지문 | `cfg_hash` + 명령어 n-gram MinHash → LSH |
| BM25 | 큐레이션된 토큰 스트림 (아래) |
| 임베딩 | 문맥화 요약 대 요약. `embedding_model_version` 필수 저장 |

**BM25 토큰 스트림**: 원시 의사코드를 넣지 않는다 — `uVar1`, `local_28`, `undefined4`가 상위를 차지한다. 넣을 것은 임포트 API 이름, 문자열 리터럴, 희귀 상수, 명령어 n-gram. 희귀 32비트 상수(`0x9E3779B9`, `0xEDB88320`, S-box 시퀀스)는 거의 고유 식별자다.

**임베딩**: 원시 코드가 아니라 문맥화된 요약을 임베딩한다. 문맥 = 바이너리 정보 + 콜그래프 위치 + 사용 API + 참조 문자열. 질의 시 저가 모델로 임시 요약을 만들어 요약 대 요약으로 매칭하고, **임시 요약은 검색 키로만 쓰며 최종 판단 컨텍스트에 넣지 않는다.**

**융합은 RRF**:
```python
def rrf(rankings: dict[str, list[str]], k: int = 60) -> list[tuple[str, float]]:
    """score(d) = Σ_channel 1 / (k + rank_channel(d))"""
```
가중합을 쓰지 않는다 — 채널마다 점수 스케일이 달라 큰 채널이 결과를 지배하고, 채널별 어블레이션 해석이 불가능해진다.

**축적 정책**:
- 쓰기 게이팅: `source in ('human','emulation')` 또는 confidence 임계 이상만 색인(불변식 6). 게이팅은 색인 함수 진입부에서 강제한다.
- 정규 엔트리 클러스터링: 같은 함수가 50개 샘플에 있어도 `entries`는 하나, `occurrences`가 출현을 담는다.
- IDF 가중: 출현 빈도가 높은 엔트리는 정보량이 낮으므로 누른다.
- 모든 질의에 `superseded_by IS NULL`.

## 8. L5 산출물

- **Ghidra 프로젝트**: DB → Ghidra 단방향 apply. 리네임·주석 반영.
- **findings**: 근거 인용을 **원문 그대로** 저장한다. §6의 환각률은 인용 문자열이 바이너리/DB에 실제 존재하는지 대조해 자동 검증되므로, 인용을 요약하거나 다듬으면 그 검증이 불가능해진다.
- **ATT&CK 매핑 / IOC**: findings에서 파생한다. 근거 없는 매핑을 만들지 않는다.
- **마크다운 리포트**: 모든 주장에 `run_id`와 근거를 붙인다. API 키·경로 등 민감 정보가 리포트로 새지 않는지 확인한다(§10).
