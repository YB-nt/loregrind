## 배경

L1 사실이 갖춰졌으므로 에이전트가 그것을 읽을 통로가 필요했다. 동시에 이 단계에서
**처음으로 바이너리 유래 텍스트가 LLM 으로 나간다.** 1주차에는 격리할 프롬프트 조립
코드 자체가 없어 §10 인젝션 격리가 유보 상태였고, 여기서 더 미루면 격리 없는 프롬프트
경로가 먼저 생긴다.

## 설계 결정과 근거

### 1. 도구 로직과 MCP 바인딩을 분리했다 (`api.py` / `server.py`)

`server.py` 에는 로직이 없다. 이유 두 가지 — (a) 전송 계층을 띄우지 않고 도구 계약을
테스트할 수 있다(18건 전부 SDK 없이 돈다), (b) SDK 버전이 바뀌어도 계약이 흔들리지
않는다. MCP SDK 2.0.0 은 이 프로젝트가 처음 쓰는 외부 런타임 의존성이다.

### 2. 도구는 예외를 던지지 않고 실패를 반환한다

MCP 에서 예외는 전송 계층 오류가 되고, 그러면 에이전트가 **"도구가 고장났다"와
"그 주소에 함수가 없다"를 구별하지 못한다.** 전자는 재시도, 후자는 다른 주소를
찾아야 하는데 행동이 갈린다.

### 3. `NOT_EXTRACTED` 를 빈 결과와 구별했다

v1 로 적재된 바이너리에서 `search_strings` 가 빈 배열을 주면 에이전트는 "문자열이
없는 바이너리"로 읽는다. 실제로는 추출하지 않은 것이다. `EVAL-SPEC.md` 의
"측정 불가는 0% 가 아니다"를 도구 응답에 적용했다.

### 4. `strategy="rank"` 를 순차 순서로 대신하지 않고 거부한다

없는 랭킹을 있는 척하면 §6 어블레이션 2축(랭킹 vs 순차 vs 랜덤)의 **기준선이 오염되고,
그 오염은 지표 표에 드러나지 않는다.** L3 가 붙을 때까지 `NOT_EXTRACTED` 를 반환한다.
같은 이유로 `sequential` 전략의 `score` 는 `0.0` 이 아니라 `null` 이다.

### 5. 격리는 `analyze/context.py` 한 곳에서만 한다

도구는 원문을 반환한다. 두 곳에서 감싸면 이중 이스케이프된다. 대신 `UNTRUSTED_KINDS`
등록제를 두어, 등록되지 않은 종류로 감싸려 하면 `ValueError` 로 세운다 — 새 데이터
경로가 격리 목록 밖에 조용히 남는 것을 막는다.

### 6. 속성값 이스케이프를 본문과 다르게 했다 (**테스트가 잡은 실제 구멍**)

처음 구현은 본문의 `<untrusted` / `</untrusted` 시퀀스만 막았다. 그런데 속성값에
따옴표 하나(`0x1" onload="evil`)를 넣으면 **속성을 빠져나가 여는 태그에 임의의 속성을
덧붙일 수 있었다.** `escape_attr` 를 분리해 `"` `'` `>` 를 엔티티로, 줄바꿈을 공백으로
바꾼다. 테스트를 고치지 않고 코드를 고쳤다.

### 7. 예산은 토큰·비용·**도구 호출 횟수** 세 축을 센다

토큰만 세면 싼 도구를 무한히 부르는 탐색이 빠져나간다. 도구 호출 계상은 인자 검증보다
**먼저** 한다 — 예산이 떨어진 뒤에도 인자에 따라 다른 응답을 주면 "아직 일한다"는
신호가 된다.

### 8. 서버 시작 시 `create_run` 을 부른다

도구 호출도 run 에 소속되어야 어블레이션이 성립한다 (불변식 5). `allow_writes` 는
`runs.config_json.rename_writes` 로 그대로 기록되어 §6 어블레이션 1축의 조작 지점이
된다. 쓰기 기본값은 **금지**다 — 기본이 허용이면 "쓰기 없음" 조건을 만들 때마다
명시해야 하고 언젠가 빠뜨린다.

## 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| `server.py` 안에 도구 로직 직접 작성 | SDK 없이 테스트 불가. SDK 버전 변경이 계약 변경이 된다 |
| 도구가 예외를 던지고 SDK 가 변환 | "고장"과 "없음"이 에이전트 쪽에서 구별되지 않는다 |
| `query(sql)` 도구 노출 | 행동 귀속 불가 → 어블레이션 무의미 (`SPEC.md` §13에서 이미 기각). 테스트로 부재를 고정했다 |
| `strategy="rank"` 를 순차로 폴백 | 어블레이션 기준선 오염 (위 §4) |
| 도구 층에서도 격리 래핑 | 이중 이스케이프 |
| 본문과 속성에 같은 이스케이프 규칙 | 따옴표 탈출을 막지 못한다 (위 §6) |
| 예산을 프롬프트 문구로 전달 | 불변식 8 정면 위반 |
| `search_strings` 를 정규식으로 | ReDoS + 질의 표현력 가변 |
| `list_candidates` 를 offset 페이지네이션으로 | 함수 목록이 바뀌면 페이지가 어긋난다. 주소 커서는 안정적이다 |

### 무엇이 미달인가 — §7 2주차는 **부분 달성**이다

완료 기준은 "함수 1개를 제대로 요약"이다. **요약을 만드는 코드가 없다.**
있는 것은 요약에 필요한 도구·프롬프트·예산이고, 없는 것은 **LLM 을 호출하는 루프**다.
`SPEC.md` §12를 2a(도구 층, 달성)와 2b(에이전트, 미달)로 쪼개 이 사실을 표에 남겼다.

### 미검증 항목

| 항목 | 이유 |
|---|---|
| **stdio 전송 실제 핸드셰이크** | in-process 로 `list_tools()` 까지만 확인했다. 실제 MCP 클라이언트를 붙여 stdio 로 주고받은 적은 없다 |
| 도구 응답의 SDK 직렬화 형태 | `dict` 반환이 structured output 으로 어떻게 나가는지 클라이언트 쪽에서 확인하지 않았다 |
| 예산 기본값 (40k / $5 / 200함수 / 30호출) | **근거 없는 초기값이다.** LLM 호출이 없으므로 실측할 대상 자체가 없었다 |
| 프롬프트의 실제 효과 | 인젝션이 격리된다는 것은 문자열 수준에서 확인했다. **모델이 실제로 따르지 않는지는 측정하지 않았다** — 그것이 §7 11주차 인젝션 성공률이다 |
| 대형 바이너리에서의 `list_candidates` | 함수 2개로 확인했다 |
| `search_strings` 의 LIKE 스캔 성능 | 문자열 수만 건에서 중간 일치는 전체 스캔이다 |
