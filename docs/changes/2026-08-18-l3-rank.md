## 배경

2주차가 닫히면서 에이전트가 함수를 읽을 수 있게 됐지만 **무엇을 먼저 읽을지 정하는
것이 없었다.** 함수 수천 개를 순차로 읽는 것은 §1 문제 정의가 애초에 배제한 접근이다.

동시에 §6 어블레이션 1축(리네임 쓰기 유무)을 재려면 쓰기 도구가 존재해야 한다 —
없는 기능의 유무를 비교할 수는 없다.

## 설계 결정과 근거

### 1. 필터는 **보수적으로** — 거짓 양성이 영구 누락이다

비대칭 비용이다. 잘못 걸러낸 함수는 **영영 안 읽히고**, 판정하지 않은 함수는 그냥
분석 대상으로 남을 뿐이다. 그래서 `classify()` 는 확신이 없으면 `None`(미판정)을
돌려준다. `is_library=False` 가 아니라 **미판정**인 것이 중요하다 — 라이브러리가
아니라는 판정과 판정하지 않은 것은 다르다.

합성 바이너리 실행에서 판정률 0% 가 나왔다. 스트립된 `FUN_*` 이름에는 적용할 규칙이
없기 때문이고, **이것이 정상 동작이다** — FID/시그니처 DB 없이 이름만으로 판정하려
들면 그때부터 거짓 양성이 나온다.

### 2. 디컴파일 실패를 라이브러리로 접지 않는다

실패는 실패다. 라이브러리로 접으면 실패율이 필터 뒤로 숨어 §7 1주차부터 세어 온
`decompile_failure_count` 가 의미를 잃는다.

### 3. 판정 근거를 별도 테이블에 (`library_verdicts`)

`functions.is_library` 만 갱신하면 "왜 걸러졌는가"를 복원할 수 없다. 필터는 분석
대상을 절반 이하로 줄이는 최대 효과의 최적화이므로, **틀렸을 때 되짚을 수 있어야
한다.** 컬럼은 파생 캐시이고 진실은 `library_verdicts` 에 method·version 과 함께
append 된다 (`SPEC.md` §7).

### 4. 신호별 점수를 따로 저장한다

`function_scores` 에 `s_api`/`s_strings`/`s_callgraph`/`s_complexity`/`s_capa` 를
각각 남긴다. **합계만 남기면 "어느 신호가 값을 했는가"를 물을 수 없고**, 그것은
§6 어블레이션이 요구하는 질문이다.

`s_capa` 만 NULL 허용이다 — capa 는 선택 의존성이고, 미설치를 0 으로 채우면
"규칙에 안 걸림"과 구별되지 않는다.

### 5. 가중합을 쓴다 (여기서는 허용)

§5 가 RRF 를 요구하는 것은 **검색 채널 융합**이다. 여기는 채널이 아니라 신호이고
전부 0..1 로 정규화되므로 가중합이 성립한다. 가중치는 `Weights` 로 `runs.config_json`
에 실려 어블레이션 축이 된다. **오타난 가중치 키는 거부한다** — 조용히 무시되면
어블레이션이 거짓말을 한다.

### 6. 동점은 주소 오름차순으로 깬다

`sorted(key=lambda s: (-s.score, s.addr))`. dict/set 순서에 맡기면 재현이 깨지는데
증상이 "가끔 순서가 다르다"라서 눈에 안 띈다 (불변식 4).

### 7. 세 전략이 같은 응답 shape 을 쓴다

`rank`/`sequential`/`random` — §6 어블레이션 2축. shape 이 갈리면 소비 코드가
전략마다 갈라지고, 그 순간 비교 대상이 "전략"이 아니라 **"전략 + 소비 코드"** 가 된다.

`random` 은 `runs.seed` 를 요구한다. **시드 없는 무작위와 비교한 개선폭은 숫자가
아니다.** 시드가 없으면 `NOT_EXTRACTED` 로 거부한다.

`rank` 는 점수가 없으면 순차로 대신하지 않고 거부한다 — 없는 랭킹을 흉내내면
어블레이션 기준선이 오염되고 그 오염은 표에 드러나지 않는다.

### 8. 쓰기 도구는 기본 꺼짐, `WRITE_DISABLED`

`allow_writes` 가 §6 어블레이션 1축의 조작 지점이다. 기본이 켜짐이면 "쓰기 없음"
조건을 만들 때마다 명시해야 하고 언젠가 빠뜨린다. 네 도구 전부 `_write_guard` 를
지나고, 꺼진 상태에서 판단이 하나도 안 들어가는 것을 테스트가 고정한다.

- `record_analysis` — `source='agent'` 고정. 에이전트가 자기 신뢰 등급을 못 올린다
- `record_hypothesis` — `status='open'` 으로만 생성. **확정·반증은 에뮬레이션이 한다**
  (자기 가설을 스스로 확정하면 검증 루프가 자기 확인으로 무너진다)
- `rename_function` — DB 에만 쓴다. `applied_to_ghidra: False` (불변식 2).
  이름은 C 식별자 검사를 지난다 — L5 apply 에서 깨지기 전에 여기서 막는다
- `set_comment` — 위와 같다

## 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| 미판정 함수를 `is_library=False` 로 기록 | 판정과 미판정이 같아진다. 나중에 FID 를 붙일 때 무엇을 다시 봐야 하는지 알 수 없다 |
| 이름 규칙을 스트립된 `FUN_*` 에도 적용 | 근거가 없다. 거짓 양성 = 영구 누락이므로 비대칭 비용이 크다 |
| 점수 합계만 저장 | 어느 신호가 값을 했는지 물을 수 없다 → §6 어블레이션 불가 |
| capa 미설치를 `s_capa=0` 으로 | "규칙에 안 걸림"과 구별되지 않는다 |
| 신호 융합에 RRF | 채널이 아니라 신호다. 전부 같은 스케일이므로 가중합이 더 단순하고 해석 가능하다 |
| `random` 전략을 시드 없이 | 재현되지 않는 바닥선과 비교한 개선폭은 숫자가 아니다 |
| 점수 없을 때 `rank` 를 순차로 폴백 | 기준선 오염. 표에 드러나지 않는 종류의 오염이다 |
| 가중치를 YAML 로 (`SPEC.md` 원안) | PyYAML 의존성이 늘어난다. JSON 은 표준 라이브러리로 읽힌다 — **`SPEC.md` §7 을 정정해야 한다** |
| `rename_function` 이 Ghidra 를 직접 갱신 | 불변식 2 정면 위반. 역방향 동기화 경로가 생긴다 |

### §7 3주차 완료 기준은 **미달**이다

완료 기준은 "첫 어블레이션(쓰기 유무)"이고, 판정 명령은
`make ablation METRIC=naming_accuracy AXIS=rename_writes` 가 두 조건의 행을 각각
`n>0` 으로 내놓는 것이다 (`SPEC.md` §12). 지금 결과:

```
어블레이션 결과가 비어 있다: metric=naming_accuracy, axis=rename_writes
  → 우회 집계하지 말고 계측 결함으로 다룬다 (§6)          exit=3
```

**이것이 올바른 동작이다.** 어블레이션 기계는 돌지만 넣을 숫자가 없다:

1. `naming_accuracy` 를 재려면 **정답셋**이 필요하다 (미구현, 5주차 최대 위험)
2. 두 조건을 돌리려면 **API 키**가 필요하다 (없음)

숫자를 지어내 `run_metrics` 에 넣으면 표가 채워지지만 그것은 측정이 아니다.
빈 채로 exit 3 을 내는 편이 정직하다.

### 미검증 항목

| 항목 | 이유 |
|---|---|
| **랭킹이 실제로 좋은 순서를 만드는가** | 합성 함수 2~4개로만 확인했다. "핵심 함수 발견까지 읽은 함수 수"(§6 탐색 효율)는 정답셋 없이 못 잰다 |
| 가중치 기본값 (1.0/0.8/0.5/0.4/1.2) | **근거 없는 초기값이다.** 튜닝하려면 탐색 효율 지표가 먼저 있어야 한다 |
| API 카테고리 사전 | 이름 부분 일치다. 실제 Ghidra 임포트 이름으로 검증하지 않았다 (Ghidra 미설치) |
| 라이브러리 필터의 실제 효과 | "분석 대상을 절반 이하로" 는 §3 의 주장이고, 합성에서는 판정률 0% 다. 실제 PE 에서 재야 한다 |
| capa 연동 | 선택 의존성으로 자리만 뒀다. 설치·호출 코드는 없다 |
| 쓰기 어블레이션의 실제 효과 | 리네임이 컨텍스트에 전파되는 것은 확인했다. 그것이 **명명 정확도를 올리는가**는 미측정 |
