## 설계 결정과 근거

### 1. LLM 을 프로토콜 뒤로 숨겼다

`agent.py` 는 `LLMClient` 프로토콜만 안다. 그래서 **API 키 없이, 비용 없이,
결정론적으로** 루프 전체를 테스트한다(14건). SDK 를 직접 부르면 결정론적인 부분
(도구 디스패치·예산·근거 검증·기록)이 비결정론적인 부분과 섞여 어느 쪽이 틀렸는지
구별할 수 없다.

### 2. 가격표에 없는 모델은 **거부한다**

`estimate_cost_usd` 는 모르는 모델에 0 을 돌려주지 않고 `UnknownModelPricing` 을
던진다. 0 이 기록되면 리포트에서 "비용이 들지 않았다"로 읽힌다 — `EVAL-SPEC.md` 의
"측정 불가는 0% 가 아니다"를 비용에 적용했다. 확인은 **생성 시점**에 한다. 첫 호출
뒤에 터지면 이미 돈을 쓴 뒤다.

캐시 토큰도 배수(읽기 0.1×, 쓰기 1.25×)로 따로 센다. 입력가로 뭉뚱그리면 캐시가
절약한 비용이 §6 캐시 곡선에서 사라진다.

### 3. 쓰기 도구를 부르는 것과 결과를 기록하는 것은 다르다

2주차는 읽기 전용이지만 판단은 DB 에 남아야 한다(불변식 5). 그래서 **에이전트가
쓰기 도구를 부르는 것이 아니라 루프가 최종 결과를 기록한다.** 어블레이션 1축이
조작하는 것은 "리네임이 이후 컨텍스트에 전파되는가"이고, 결과 기록은 계측이다.
테스트가 이 경계를 고정한다 — `record_analysis` / `rename_function` / `query` 는
디스패치 표에 없다.

### 4. 근거는 검증하되 지우지 않는다

존재하지 않는 근거도 `verified=False` 로 **그대로 저장한다.** 지우면 §6 환각률이
0 이 되고, 그 0 은 시스템이 좋아서가 아니라 증거를 없앴기 때문이다. 검증 방식도
`eval/metrics.py` 의 `hallucination_rate` 와 같은 부분 문자열 대조를 쓴다 — 한쪽만
느슨하면 두 숫자가 어긋난다.

### 5. 최종 답변을 JSON 스키마로 고정했다

`output_config.format` 로 `{proposed_name, summary, confidence, evidence[{kind, ref}]}`
를 강제한다. 자유 텍스트면 환각률을 잴 수 없다(`SPEC.md` §4.3).

### 6. 파싱 실패·거부·잘림을 답변으로 치지 않는다

`stop_reason` 이 `refusal`/`max_tokens` 이거나 JSON 을 못 읽으면 **판단을 만들지
않는다**(`analysis_id=None`) 그리고 `aborted` 에 이유를 남긴다. 빈 판단을 저장하면
명명 정확도의 분모가 조용히 부풀어 오른다.

### 7. `redact_config` 버그 수정 (**e2e 실행이 잡았다**)

`max_tokens_per_function: 40000` 이 `"<redacted>"` 로 저장되고 있었다 — 키에
`token` 이 들어 있다는 이유로. **이 프로젝트에서 `token` 은 비밀정보만큼이나 자주
토큰 수를 뜻하고**, 그 축은 어블레이션 대상이다. 문자열 값만 가리도록 고쳤다
(비밀정보는 문자열, 예산은 숫자).

### 미검증 항목

| 항목 | 이유 |
|---|---|
| **실제 Anthropic API 호출 전체** | **API 키가 없다.** `AnthropicClient.create` 는 한 번도 실행되지 않았다. 요청 kwargs 형태(`output_config.effort`, `output_config.format`, tools 스키마)가 실제로 받아들여지는지 미확인 |
| `_result_from_message` 의 SDK 객체 변환 | 같은 이유. `block.model_dump()` 와 `usage` 필드 이름이 이 SDK 버전에서 맞는지 미확인 |
| 모델이 실제로 도구를 부르는지 | 스텁이 부른 것이지 모델이 부른 것이 아니다. 도구 사용률·탐색 효율은 §6 지표이며 **아직 측정하지 않았다** |
| 예산 기본값 (40k / $5 / 200함수 / 30호출) | 여전히 근거 없는 값이다. 실측하려면 실제 호출이 필요하다 |
| 프롬프트 품질 | "제대로 요약"의 *제대로*는 §6 명명 정확도로 재야 하고, 그러려면 정답셋이 필요하다 (5주차 최대 위험) |
| 인젝션 저항 | 격리는 문자열 수준에서 확인했다. 모델이 실제로 따르지 않는지는 §7 11주차 지표다 |

## 미해결 / 후속

- **§7 2주차는 코드로는 완료, 숫자로는 미완이다.** 완료 기준의 "제대로"를 검증하려면
  API 키 1개 + 정답셋이 필요하다. 이 둘은 사용자 결정 사항이다.
- 다음: §7 3주차 — L3 랭킹(`library_verdicts` + 결정론 점수) + 쓰기 도구 4종 +
  **첫 어블레이션**(`make ablation METRIC=naming_accuracy AXIS=rename_writes`).
- `.env` 자동 로딩은 없다. SDK 가 환경변수를 읽으므로 사용자가 `.env` 를 환경에
  실어야 한다 — 키를 코드·DB 에 두지 않는다는 §10 은 지켜진다.
- 이 브랜치는 사용자 요청에 따라 **`develop`에 병합하지 않고 푸시만 한다.**
