## 배경

이 저장소는 Best-README-Template 스캐폴드 상태였고 Loregrind라는 프로젝트 내용이 없었다.
`docs/PROJECT.md`(286행)가 들어오면서 무엇을 만드는지가 처음으로 저장소 안에 고정됐다.

## 설계 결정과 근거

- **사양을 코드보다 먼저, 저장소 안에 둔다.** `docs/PROJECT.md`가 단일 권위이며
  `CLAUDE.md`가 "이 문서와 어긋나면 `docs/PROJECT.md`가 이긴다"로 그 우선순위를 못박았다.
  이후 하네스 스킬 5개가 전부 이 문서의 절 번호(§10, §11)를 직접 인용하는 구조가 됐다.
- **§7에 중단 지점을 명시했다.** "5주차 종료 시점에 지표가 안 나오면 6주차 이후를 전부
  잘라낸다"는 조건이 사양 안에 있다. 범위 축소 판단을 나중의 의지력에 맡기지 않는다.
- **§2에 제외 항목을 명시했다.** 언패킹, 전체 샘플 실행, ELF/Mach-O, 실시간 서비스·웹 UI·
  멀티유저. 범위 이탈 판정이 가능해진 것은 이 목록 덕분이다.

## 기각한 대안

**미기록** — 요청서 자체의 작성 과정(다른 주제·다른 범위를 검토했는지)은 이 저장소에 남아 있지 않다.
문서 안에서 확인되는 기각은 사양이 스스로 적어둔 것들이다:

| 대안 | 기각 사유 (문서 내 근거) |
|---|---|
| 전용 벡터 DB 분리 | §9 — Postgres+pgvector 하나면 구조화 필터와 벡터 검색을 한 질의에 섞을 수 있다. 분리하면 애플리케이션 조인이 되고 정확성·성능이 함께 나빠진다 |
| 검색 채널 가중합 | §5 — 채널마다 점수 스케일이 달라 큰 채널이 지배한다. RRF(순위 융합)를 쓴다 |
| 정규화 없는 코드 해싱 | §4 — 히트율이 사실상 0이 된다 |
| 바뀐 함수만 재분석 | §4 — 요약 카드 오염이 호출자로 전파된다. 콜그래프 역방향 무효화가 필요하다 |
| 얕은 기능 5개 | §7 — "얕은 5개보다 깊은 2개가 강하다" |
